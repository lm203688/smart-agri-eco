### 交付

1. **`scripts/verify_trust_mark.py`**（约 320 行，零依赖 stdlib）
   - 4 种验证模式（严格递减依赖）：
     - `check-prefix`：只读输入 mark，检查 signature_prefix 是否等于 signature 前 12 字符（结构完整性）
     - `from-certificate`：剥离 signature → canonical → SHA256 比对（证书对象自签名未被篡改）
     - `from-certificate --verify-artifacts`：最强验证——artifacts[] 声明的 sha256 vs 磁盘实际哈希（数据源未被修改）
     - `from-mark`：用 mark 声明的 issued_at + 本地数据源严格重现 signature（端到端可复现）
   - 退出码语义：0=通过 / 1=验证失败 / 2=输入错误

2. **`core/trust_layer.issue_certificate` 新增 `fixed_issued_at` 参数**
   - 此前 `issued_at` 每次运行时都用 `datetime.now()`，导致 signature 每次运行都不同，**无法外部复算**——这是"公共复算"的关键卡口
   - 修复后：外部消费者拿到 mark 后，用 `fixed_issued_at=mark['issued_at']` 严格重现 signature

3. **MCP 工具 `agri_verify_trust`**（第 19 个工具，工具数 18 → 19）
   - 3 种 mode：`current` / `check_prefix` / `end_to_end`
   - 零副作用只读，让 MCP 客户端不必先跑核心引擎也能独立验证 trust_mark

4. **`scripts/test_verify_trust_mark.py`**（34 项单测）
   - 覆盖：canonical/sha256 原语 + 4 种验证模式各分支（含篡改测试）+ CLI 6 分支 + MCP 6 分支 + trust_layer fixed_issued_at 3 分支

5. **`artifacts/agritrust_badge.svg` + `docs/agritrust_verified.md`**

### 关键设计决策

1. **诚实边界写进 schema 与 API 输出**：`signature` 是内容一致性 SHA256（非密码学签名，无密钥），必须诚实标注"证明数据未被修改，不证明签发者身份"
2. **端到端复算必须用 `fixed_issued_at`**：这是"公共复算"能兑现的核心机制，否则 mark 每次生成 signature 都不同
3. **`--verify-artifacts` 是最强验证**：不仅证书对象自签名一致，其引用的数据文件（`data/zone_meta/global_zones.json`、`data/crop_adapt_db.json`）也未被修改
4. **不静默通过**：任何降级/缺失返回 `verified=False` + 具体原因，绝不伪装"已验证"
