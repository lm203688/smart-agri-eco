# Env Recipe 协议 v1（环境配置配方）

> 状态：v1.0.0 草案 · 2026-09-05
> 配套：见 `schemas/env_recipe.schema.json`（JSON Schema）、`data/examples/sample_env_recipe.json`（样例）
> 定位：全球农业「可机读底座」与「配置协议」的核心交付物（评审建议 #3 / #9：从远期卡位升为近期最高优先）

---

## 1. 一句话定义

**一份 Env Recipe = 作物 × 生长阶段 × 箱体条件 → 温湿 / 光谱 / PPFD / CO₂ / EC / pH / 水肥 / 气流 / 异常处理 的可执行参数集。**

它是所有种植硬件与 Agent 共享的「配方语言」：硬件厂、存量智能种植机、开源种植项目、农业 Agent 全部用同一种 JSON 描述「这个作物在这个箱子里该怎么长」。

---

## 2. 为什么是近期最高优先（而非远期）

评审核验了一组行业事实（2026-09 检索）：

- **垂直农场大出清**：Plenty（2025-03 Chapter 11）、Bowery（2024 末停运）、AppHarvest（2023-07 破产）、AeroFarms（2025-12 关最后一家）。失败机制一致：能源占运营成本 50-70%、先扩产能后验证单位经济。
- **C 端智能种植机变砖**：AeroGarden（Scotts Miracle-Gro 旗下，2006 开品类）2024-10 宣布关停，数百万 Wi-Fi 设备因 App 前景不明沦为「孤儿设备」——IoT 行业反复上演的变砖剧本。Ars Technica 报道中有用户公开呼吁 open-source 协议自救。

**结论**：我们不碰硬件、不卖箱子（评审 #2）。但 Env Recipe 开放协议恰好解决孤儿设备的「大脑缺失」——**这是一个当下就有真实需求方的切口**，不是远期赌注。

---

## 3. 协议字段与 day-1 留位（最重要的一条工程纪律）

`environment` 是配方核心（温度/湿度/光/CO₂/水肥/气流）。但真正构成护城河的是三个 **day-1 必须留位、且当前全行业空白** 的字段：

| 字段 | 独占数据 | 为什么 day-1 留位 |
|---|---|---|
| `execution_log` | **独占数据 A**：配方→执行→结果三元组的执行侧 | 事后补字段要回填历史运行，几乎不可能；它是训练「环境→结果」预测模型的唯一燃料 |
| `outcome` | **独占数据 A**：执行结果（产量/品质/失败原因） | 与 `execution_log` 配对才有价值；全球无任何公开数据集含「此配方在此箱长出何结果」 |
| `image_consent` | **独占数据 B**：中文病虫害图像授权 | PlantVillage 以欧美作物为主，中文场景标注图像是真空白；采集端即声明授权，避免事后法律/伦理返工 |

> 组织方式、API 化、MCP 分发——巨头一个季度能抄走。只有「闭环回流数据」是时间无法被别人追平的资产（评审 #7）。这三个字段就是为它留的位。

## 4. 设备如何采用（接入路径）

### 4.1 硬件厂 / 开源种植项目
1. 拉取 `schemas/env_recipe.schema.json` 作为设备固件的配置契约；
2. 设备每次运行，把实际参数写入 `execution_log`、把结果写入 `outcome`；
3. 基础配方 `CC-BY-4.0` 免费；高级配方包（稀缺作物 / 高价值阶段）走商用授权（评审收入模式 A）。

### 4.2 AeroGarden 等孤儿设备社区
- 设备 App 已停更 → 用本协议的 `device_class: aerogarden_orphan` 标注；
- 社区可凭 `device_id` 对账、共享配方、用 `outcome` 互相校准；
- 这正是「给存量设备提供配方大脑」（评审 #2 修正）的落地形态。

### 4.3 农业 Agent / MCP 调用方
- 见 `mcp/server.py` 的 `agri_env_recipe` 工具：输入 作物 + 阶段 + 设备类，返回一份 schema 合规的 Env Recipe。
- Agent 拿到配方即可下发到执行器，无需理解农艺细节。

## 5. 版本与许可

- `recipe_version` 语义化版本（当前规范 `1.0.0`）；`protocol` 固定 `env-recipe`。
- 基础配方 `CC-BY-4.0`；高级配方包可商用授权（参考 SwarmLabs license ¥39.9-199 的自服低摩擦定价）。
- 破坏性字段变更 → 升主版本；新增可选字段（如未来 `carbon_credit` 碳汇字段）→ 不改主版本，保持向后兼容。

---

## 6. 外部验证钩子（P0-G 决策门）

本协议发布后，主动投递两个社区验证「开放配方协议」是否真有需求方：

- **GitHub + 种植机开发者社区 / 开源硬件项目**（如 Arduino/ESP32 种植控制器、Home Assistant 种植集成）；
- **AeroGarden 孤儿设备自救社区**（Reddit / 独立论坛，Ars Technica 报道中已有呼吁）。

**决策门**：发布后 3 个月内若 **零 issue / 零 PR / 零社区讨论** → 说明协议当前市场未熟，降级为内部配置格式，停止对外投入（评审 §3.5 放弃条件）。
