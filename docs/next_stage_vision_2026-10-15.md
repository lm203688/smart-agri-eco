## 0. 一句话主张

> **2026 年农业 AI 的主战场是"更大的模型"——神农世界模型、司农 LLM、OneGenome-Rice 基因组基础模型、四大农业大模型同日发布。这条路本项目走不了，也不必走。**
>
> **本项目下一阶段的跃迁方向不是"做一个更强的农业模型"，而是成为整个农业 Agent 生态里唯一缺失的那一层：**
>
> ### **「农业决策的验证层 + 可执行的数字孪生」**
> ### *(Verifiable Agricultural Decision Layer)*
>
> **别人负责"给出建议"，我们负责"证明这个建议在这个环境下、对这个用户、会不会成立"。**
>
> 这一层之所以无人占领，是因为它同时要求四件互相冲突的能力：**① 本地可离线运行（否则拿不到微场景数据）② 可解释可复算（否则无法验证）③ 有不确定性保证（否则不能担责）④ 能从极少样本中校准（否则冷启动不了）**。大模型路线天然不满足 ①③④，规则路线天然不满足 ③④，云 API 路线天然不满足 ①。
>
> **而本项目——零依赖 + 可溯源 + 保形区间 + 影子运行——恰恰四件都已有雏形。这不是巧合，是过去两个月在无意识中走对了方向。下一阶段要做的是：把这四个雏形，焊成一个别人抄不走的系统。**

## 2. 战略判断：市场环境已经变了

### 2.1 2026 年农业 AI 的真实格局（检索实证）

| 阵营 | 代表（2026） | 路线 | 能力边界 |
|---|---|---|---|
| **农业世界模型** | **神农·农业世界模型**（中国农大，2026-07，**全球首个动作条件化、设施+大田双域验证**） | 世界模型 + 强化决策 | 需训练栈；数据来自大田/设施；**覆盖不到分布式微场景** |
| **农业垂直 LLM** | **司农**（南农，2026-01 开源）· 四大农业大模型（2026-05 同日发布） | 领域语料预训练 | 生成知识；**不产出可执行配置、不给不确定性保证** |
| **基因组基础模型** | **OneGenome-Rice**（12.5 亿参数，2026-04 开源） | 基因组序列建模 | 育种端；与种植决策链不接 |
| **作物机理模型** | DSSAT（已全面开源）/ APSIM / PCSE-WOFOST / **AgroSim**（统一 YAML 编排） | 机理模拟 | 科学深度最足；**重依赖、无 Agent 接口、不服务微场景** |
| **云集成 MCP** | FieldMCP（$29/org/月，150+ tools）/ Leaf / Trimble | API 封装 | 工具数量竞争；**离不开云、只服务大田** |
| **HA 配方生态** | Horticulture-Assistant / OpenGrowBox | 家庭自动化 | 绑死 HA 运行时；无知识底座、无回流 |
| **本项目** | 智慧农业生态 | 零依赖 + 可执行配置 + 可验证 | **四阵营的盲区交集** |

### 2.2 三个正在发生的结构性变化

**变化一：从生成式 AI 到代理式 AI——协议栈正在重构。**
2026 年智能体协议栈已成型：**MCP（上下文/工具连接）+ A2A（智能体间通讯）+ AG-UI（动态交互）+ UCP/AP2（交易支付）**。这意味着**"智能体之间互相调用、互相验证、互相付费"将变成基础设施**。本项目已占 MCP + A2A 位，**但仍是"被调用的工具"，尚未成为"被调用的裁判"。**

**变化二：农业 AI 的瓶颈已从"预测不准"转向"不敢用"。**
神农的四轴评价协议直指"高精度 ≠ 可决策"。所有农业大模型都面临同一个信任问题：**农户凭什么相信你的建议？错了谁负责？** ——**这正是"验证层"存在的理由，且它比"生成层"更接近商业闭环。**

**变化三：微场景数据是大模型永远拿不到的。**
阳台、屋顶、社区、车载这些分布式微场景，数据分散在千万个用户手里，**隐私敏感、单点样本极少、环境各异**。任何中心化大模型都拿不到这些数据；**而谁能让用户"不上传原始数据也能贡献知识"，谁就独占这片数据。**

### 2.3 本项目的战略位置（一句话）

> **四大阵营各有各的"做决策"的能力，但没有任何一方在做"验证决策"。**
> **而当一个生态里开始出现多个互相竞争的决策者时，"第三方验证"就从可选项变成必需品。**
>
> **本项目应该做的不是第五个决策者，而是第一个验证者。**

### 2.4 一个必须直面的反对意见（诚实列出）

**反对**："验证层是不是太小众？用户其实只想要一个能用的建议，不关心验证。"

**回应（三层）**：
1. **短期确实如此**——所以验证层不能是唯一卖点，必须与"更好的建议"捆绑（§3 的 AgriWorld-Lite 同时提升两者）。
2. **中期是护城河**——当多个农业 Agent 给用户互相矛盾的建议时（这在 2026 年已经是常态），**"谁说得对"就是刚需**。
3. **长期是商业模式**——**可验证 = 可担责 = 可定价**。不能验证的建议永远只能是免费的；能验证、能归因、能界定责任的决策，才能收费、才能进保险与金融场景（这与 M16 投资初筛天然衔接）。

## 3. 一个需要重新评估的既有决策：A2 机理模型

**MEMORY §四把"A2 机理模型"列为「明确不做」。本作建议重新评估，理由如下：**

| 当时的理由（合理） | 本作的重新评估 |
|---|---|
| 超 §八 P1 例外范围 | 机理内核属"科学内核"，与"可验证方法层"同属 D3 例外精神 |
| 工作量大（7-10 天） | 可分阶段：v0 只做**光截获 + 同化 + 分配**三段，约 5-7 天 |
| G1 前不应分散精力 | **G1 的唯一路径是人工（SSH/Glama），Agent 侧无论如何都要等** —— 等待期正是做科学内核的窗口 |

**关键论证**：
- **保形预测解决的是"区间有多宽"，解决不了"均值有多准"。** 当前 92% 覆盖率很漂亮，但如果点估计本身来自启发式乘数，**区间再准也是在精确地包围一个可能偏离的值**。
- **反事实轴（17 用例）要变成产品能力，必须有"如果改变动作会怎样"的推演引擎——这本质上就是机理模型。** 没有它，反事实只能靠规则插值，站不住。
- **机理模型是本项目唯一能同时提升"科学性"与"先进性"两个分数的东西**，也是 §4 六大支柱中三根支柱的地基。

**建议**：**以"可微分、可解析梯度、零依赖"的轻量机理内核（AgriWorld-Lite）形式重启 A2，而不是照搬 DSSAT/APSIM。** 它与"验证层"愿景是同一件事的两面：**没有机理内核，验证层只能验证别人的模型；有了机理内核，验证层有了自己的物理基准。**

### 支柱一 · AgriWorld-Lite：零依赖可微分微场景数字孪生

#### 定位
**这是科学性跃迁的地基，也是"可执行"三个字的物理载体。**
不是照搬 DSSAT/APSIM（重依赖、大田导向），而是**为微场景（盆栽/阳台/温室/植物工厂）定制的轻量机理内核**——**状态少、参数少、可解析求导、零依赖**。

#### 状态空间设计（微场景特化）

| 状态变量 | 符号 | 说明 |
|---|---|---|
| 发育进程 | DVI | 0=出苗, 1=开花, 2=成熟（WOFOST 式） |
| 叶面积指数 | LAI | 光截获的核心 |
| 器官干重 | W_lv / W_st / W_so | 叶/茎/贮藏器官 |
| 根区含水量 | θ | 基质水（无土场景用基质水力而非土壤） |
| 根区氮/EC | N_avail / EC | 养分有效性 |
| 冠层温度 | T_canopy | 与气温的差异驱动胁迫 |

**为什么是这套状态**：微场景与大田的根本差别是**根区体积小、缓冲能力弱、环境可控**——所以水分与养分 dynamics 用**基质水力（van Genuchten 简化）**而非大田土壤水模型，且**控制动作（补光/通风/灌溉/加肥）直接作为输入**。

#### 机理内核三段（v0 范围）

| 段 | 方法 | 开源/学术来源 | 零依赖可行性 |
|---|---|---|---|
| **① 光截获** | Beer-Lambert：`I_abs = I_0 · (1 − exp(−k · LAI))`，k=消光系数 | WOFOST/PCSE 公开方法 | ✅ 纯 `math` |
| **② CO₂ 同化** | 冠层同化率（负指数光响应 × 温度修正 × CO₂ 修正 × 水分胁迫） | WOFOST/Farquhar 简化（矩形双曲线） | ✅ |
| **③ 同化物分配** | 发育期依赖的分配系数表（营养生长 → 生殖生长切换） | WOFOST 分配表（公开参数） | ✅ |
| **④ 维持呼吸 + 生长呼吸** | Q10 温度依赖 + 器官特异性维持系数 | Penning de Vries（公开） | ✅ |
| **⑤ 蒸腾** | **Penman-Monteith 简化**（FAO-56 公开标准）× 冠层导度 × VPD | FAO Irrigation Drainage Paper 56 | ✅ 且复用已有 VPD |
| **⑥ 根区水/养分平衡** | 水量平衡（灌溉 − 蒸腾 − 渗漏）+ 养分吸收（蒸腾驱动的质量流） | 已有 nutrient_solution 721 行可复用 | ✅ |

#### 关键设计：**可解析梯度（Analytic Gradient）**

> **这是本项目与所有开源作物模型的分水岭设计。**
> 不用 autograd（需要 PyTorch/JAX，违反零依赖），而是**手工推导状态方程对参数与控制的偏导数**，随仿真一并输出。

**为什么这很重要**（三重收益）：
1. **参数校准**：有梯度即可用梯度下降做参数反演——**这是"3-5 条实测就能校准一个作物"的前提**（支柱二）
2. **最优控制**：有梯度即可做**模型预测控制（MPC）**——直接输出"最优灌溉/补光策略"而非"建议"
3. **敏感性分析**：`∂Y/∂参数` 直接给出"哪个参数最值得用实测去标定"——**主动实验设计（Active Experiment Design）**

**判定标准**：给定参数扰动，解析梯度与有限差分（数值）梯度的相对误差 < 1e-5（可用有限差分做 golden 测试）。

#### 反事实轨迹（Counterfactual Trajectory）

```
输入：当前状态 S0 + 候选动作序列 A = [a1, a2, ..., aT]
输出：轨迹分布 {S_t}, {Y_T}，带保形区间
     + 归因：ΔY 分解到 (光/温/水/肥/发育) 各因子
```

**这一步把 Bench 的 counterfactual 轴（已有 17 用例）从"评测指标"升级为"产品能力"**——用户问"如果我把光周期从 12h 改成 16h 会怎样"，系统给出**有物理依据的轨迹对比**，而不是规则插值。

#### 与启发式的关系：**双轨 + 分歧告警**
- 保留现有启发式（已被 69 个 bench 用例验证）
- 机制轨与启发式轨并行，**分歧超过阈值时降置信度 + 显式标注**
- **这本身就是"诚实暴露不确定性"的最强表达**：两个独立方法不一致 = 我们真的不确定

#### 工作量与判定
| 项 | 值 |
|---|---|
| 工作量 | v0（①②③④）5-7 天；v1（⑤⑥ + 梯度）5-7 天 |
| 零依赖 | ✅ 全部纯标准库 |
| 判定标准 | ① 与公开 WOFOST 参考轨迹对比，主要状态量偏差 <15%；② 解析梯度 golden 通过；③ 双轨分歧可检测 |

### 支柱二 · Hybrid Calibration：机理骨架 + 保形残差的小样本校准

#### 定位
**这是先进性跃迁的引擎——它回答了那个致命问题："你没有数据，凭什么比大模型准？"**

#### 核心思路（三层结构）

```
     预测 = 机理先验（物理，可外推） + 残差模型（数据，可学习） ± 保形区间（有保证）
             ↑                          ↑                        ↑
        AgriWorld-Lite            低维线性/核岭回归          conformal.py（已有，扩展）
        零样本即可用               3-5 条实测即可拟合         92% 覆盖率已验证
```

**为什么这个结构在微场景是"最优解"**：
- **纯数据模型**（大模型/ML）：微场景样本极少（一个阳台一年 3-5 茬），**必然过拟合**
- **纯机理模型**：参数不准，**系统偏差大**
- **混合**：机理负责"形状"（外推可靠），残差负责"平移"（数据可学），保形负责"诚实边界"
- **这是"代理辅助校准（surrogate-assisted calibration）+ 残差建模（residual modeling）"的标准范式，但在农业微场景落地，2026 年尚无人做**

#### 三个技术组件

| 组件 | 方法 | 来源 | 零依赖 |
|---|---|---|---|
| **参数反演** | 贝叶斯 MAP：先验（文献参数）+ 似然（实测残差）→ 后验；零依赖用**坐标下降 + 解析梯度**或**简化 MCMC** | 标准贝叶斯校准 | ✅ |
| **残差模型** | 核岭回归（RBF 核，样本少时矩阵极小，纯 `math` 可解 n<50 的线性系统） | 经典 kernel methods | ✅ |
| **条件保形** | 从 marginal conformal 升级到 **conditional conformal**（按作物/分区/生育期分组，保证组内覆盖） | Conformal Prediction 前沿（2025-2026） | ✅ |

#### 主动实验设计（Active Experiment Design）—— 差异化杀招

> **这是"远远领先市场"的一个具体点。**

**问题**：用户只有有限次的种植机会，哪次实验最值得做？
**答案**：用机理模型的**参数敏感性 + 当前不确定性**，计算每个候选动作的**信息增益**，推荐"最能减少未来误差"的那次。

```
推荐逻辑：不是推荐"产量最高的方案"，
         而是推荐"产量不错 + 信息量最大"的方案
         （multi-objective: exploitation vs exploration, 即 bandit 思路）
```

**这在农业领域几乎是空白**：所有农业 AI 都在做 exploitation（给最优建议），**没有一个在做"帮用户设计实验"**。而这恰恰是**数据从 0 到 1 的唯一低成本路径**——**它直接破解了"feedback 0"的鸡生蛋问题**。

#### 判定标准
- 用 3 条模拟实测校准某作物，误差较未校准下降 >30%（可在隔离沙盒中用合成数据验证，**标明 synthetic**）
- 条件保形：每组（作物×分区）覆盖率 ≥90%
- 主动实验推荐：信息增益可计算、可比较

### 支柱三 · VDC：可验证决策契约（Verifiable Decision Contract）

#### 定位
**这是产品化的终点——把"一条建议"变成"一份可执行的、有责任边界的契约"。**

#### 契约结构（草案）

```json
{
  "contract_id": "vdc-2026-xxxx",
  "party": {"agent": "smart-agri-eco", "version": "1.2.0"},
  "premise": {                          // 前提：环境必须落在这些区间内
    "zone": "subtropical_wet",
    "temp_range": [18.0, 28.0],
    "vpd_range": [0.6, 1.4],
    "dli_range": [12, 30]
  },
  "action": { /* Env Recipe 引用 + 关键动作序列 */ },
  "commitment": {                       // 承诺：结果分布（保形区间）
    "yield_g": {"p10": 240, "p50": 280, "p90": 315, "method": "conformal", "coverage": 0.90},
    "duration_days": {"p10": 40, "p50": 45, "p90": 52}
  },
  "breach_rule": {                      // 违约判定与归因
    "if_observed_below_p10": "归因分析：环境偏离 / 参数误差 / 模型结构误差",
    "attribution": {"env_deviation": 0.62, "param_error": 0.28, "structure": 0.10}
  },
  "remedy": { /* 补偿动作建议 */ },
  "verification": {                     // 可独立复算
    "trust_mark": "sha256:...",
    "recompute_endpoint": "/api/verify",
    "inputs_hash": "..."
  }
}
```

#### 为什么这是"下一阶段"的关键

| 转变 | 从 | 到 |
|---|---|---|
| 交付物 | 一条建议文本 | 一份**有前提、有承诺、有违约判定**的契约 |
| 信任来源 | "我们很专业" | **可独立复算（T-1 已做，扩展到契约级）** |
| 出错时 | 无法界定责任 | **可归因**（环境偏离 62% vs 参数误差 28%） |
| 商业模式 | 免费工具 | **可定价、可进保险/金融**（与 M16 投资初筛天然衔接） |

> **一句话**：**不能验证的建议永远只能免费；能验证、能归因、能界定责任的决策，才能收费。**

#### 判定标准
- 一条建议可导出为 VDC JSON
- 第三方可用 `recompute_endpoint` 独立复算得到相同 trust_mark
- 违约归因可输出三项分解

### 支柱四 · Federated Calibration Protocol：联邦校准协议

#### 定位
**这是数据壁垒的唯一解法，也是本项目对大模型路线的结构性优势。**

#### 核心命题

> **微场景数据分散在千万个阳台/温室里，隐私敏感、单点样本极少。中心化大模型拿不到这些数据——不是技术问题，是信任问题。**
> **而"零依赖本地优先"的架构天然能做一件事：让用户贡献知识，但不贡献数据。**

#### 协议设计（v0）

```
本地（零依赖）：
  1. 本地运行 AgriWorld-Lite，用本地实测数据校准
  2. 只导出：参数增量 Δθ 与 残差统计量（均值/方差/样本数）
     —— 不导出任何原始环境/产量数据
  3. 用户显式同意 + 可撤回

聚合端：
  4. FedAvg 简化聚合：θ_global ← Σ(n_i · θ_i) / Σ n_i
  5. 回发全局先验（作为新用户的冷启动先验）

隐私增强（v1）：
  6. 加噪（差分隐私，ε 可配置）；或安全聚合（简化 secret sharing）
```

#### 为什么这能形成壁垒

- **大模型路线**：要数据 → 用户不给（隐私）→ 永远缺微场景数据 → 微场景永远不准
- **本项目**：不要数据 → 只要增量 → 用户愿意 → **数据越用越多 → 越用越准 → 后来者无法追赶**

**这是"零依赖"从限制变成资产的完整闭环**——也是本作最重要的战略论证。

#### 判定标准
- 协议文档 + 本地导出/聚合/导入的最小实现（可用 3 个模拟节点验证，**标明 synthetic**）
- 导出的增量中不含任何原始可识别数据（可审计）
- 聚合后全局先验在 held-out 节点上优于任一单点先验

### 支柱五 · Verify-as-a-Service：成为农业 Agent 的验证者

#### 定位
**这是生态位的确立——从"被调用的工具"变成"被调用的裁判"。**

#### 核心工具（建议新增第 22 个 MCP 工具）

```
agri_verify_recommendation(claim, context) → {
    verdict: "supported" | "contradicted" | "unverifiable",
    our_estimate: {p10, p50, p90},
    claimed_value: ...,
    deviation: ...,
    contradictions: [ {...} ],        // 与物理/农艺约束的冲突
    evidence: [ ... ],                 // 可复算的证据链
    trust_mark: "sha256:..."
}
```

**输入**：任何一个第三方（另一个 Agent、一个大模型、一份 BP、一个农艺师）给出的农业主张
**输出**：**它成立吗？在什么前提下成立？不确定性多大？和物理约束冲突吗？**

#### 三类可验证的冲突（这是真正的专业深度）

| 冲突类型 | 检测方法 | 例子 |
|---|---|---|
| **物理约束冲突** | 能量/物质守恒、光热上限、蒸腾-水分平衡 | "每平米产 50kg 生菜" → 光能转化效率超理论上限 → contradicted |
| **物候冲突** | 积温-发育期一致性 | "30 天收获番茄" → TSUM 不足 → contradicted |
| **环境-品种冲突** | 生态位适宜度 + 概率化分区 | "在热带种温带品种" → 分区分布给出低概率 → contradicted |

#### 为什么这个生态位无人占领

- **大模型厂商**：不会做（等于承认自己可能对）
- **云 MCP 厂商**：做不了（没有本地物理基准）
- **学术**：有兴趣无工程（缺 Agent 接口）
- **本项目**：**有物理基准（机理内核）+ 有不确定性保证（保形）+ 有溯源（T-1）+ 有 Agent 接口（MCP/A2A）**——四件齐全

#### 判定标准
- 注入 10 个已知错误主张，检出率 100%；10 个正确主张，误报率 0%
- 验证结果可导出为 VDC 式的证据链

#### 2026 年智能体协议栈（检索实证）
**MCP（工具/上下文）+ A2A（智能体通讯）+ AG-UI（交互）+ UCP/AP2（交易支付）**——被称为"自 HTTP 以来最深刻的互联网基础设施重构"。

## 10. 结语：从"做得对"到"无人能做"

> 过去两个月，这个项目把一件很难的事做成了：**在零依赖的约束下，建起了一套门禁全绿、可溯源、可复算、有不确定性保证的工程体系。785 项单测、69 个评测用例、92% 的覆盖保证——这是"做得对"。**
>
> **但"做得对"不等于"无人能做"。** 785 项单测别人也能写，21 个工具别人也能做，甚至 69 个用例的评测别人也能抄。
>
> **真正无人能做的，是这套约束的组合：**
> - **零依赖** → 别人做不到（因为他们的架构从第一天就依赖云、依赖框架、依赖模型）
> - **本地优先** → 别人不敢做（因为他们的商业模式依赖数据回流）
> - **有数学保证的不确定性** → 别人不做（因为承认不确定会削弱营销）
> - **可独立复算** → 别人不能做（因为一旦可复算，错误就藏不住）
>
> **这四条约束互相加强，构成了一个正反馈闭环：越本地 → 越能拿到微场景数据 → 越需要小样本校准 → 越依赖机理内核 → 越需要可验证 → 越需要本地。**
>
> **下一阶段要做的，不是往这个系统里再加零件，而是把这个闭环焊死——让它自己转起来，并且让任何想抄的人，都必须先放弃自己最核心的利益（数据、云、营销确定性）。**
>
> **做到这一点，"领先市场"就不再是一个目标，而是一个副产品。**
