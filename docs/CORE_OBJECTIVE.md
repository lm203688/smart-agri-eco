## 一、一句话定位（最终定稿）

> **分布式农业的 Agent-native 知识基座**——把「在哪里种什么、怎么种得好」做成**可被任何 AI Agent 直接调用**的可执行配置（Env Recipe），并以**可审计的数据血缘**作为可信度资产。

三个关键词，缺一不可：

| 关键词 | 含义 | 反面（明确不要） |
|---|---|---|
| **Agent-native** | 主交付形态是 MCP 工具 / A2A Agent Card / Agent Plugin，被其它 agent 消费 | ❌ 不是给终端用户点开的 App |
| **知识基座** | 交付的是**可执行配置 + 溯源证据**，不是原始数据搬运 | ❌ 不是又一个 Open-Meteo wrapper |
| **分布式农业** | 面向个人 / 家庭 / 社区 / 车载 / 城市微场景 | ❌ 不做大田精准农业、不做卫星遥感 |

## 二、核心目标（三层，按可验证性排序）

### G1 · 一级目标（唯一决定性指标）

> **让本项目的 MCP server 被外部 agent 真实调用。**

- **判定数字**：累计外部调用 ≥ **500 次**、独立调用方 ≥ **20 个**（`north_star_and_phase_gates.md` 门槛 7/8）
- **为什么是唯一**：在 0 外部调用状态下，其它一切指标（采纳率、回流率、收入）在数学上都不可测。**未发生第一次外部调用之前，所有新增功能都是无效投入。**
- **决策门**：评审 §3.5 已定——P0-F/G 若 **3 个月内零外部调用**，项目降级为个人知识库。启算日约 2026-09 中旬，**窗口截止约 2026-12 中旬**。

### G2 · 二级目标（被调用之后才激活）

> **把调用转化为回流数据，让配方从"文献推导"变为"实测校准"。**

| 指标 | 目标 | 激活条件 |
|---|---|---|
| `feedback_log` 真实回流（非 dry-run / 非合成） | ≥ **30 条** | G1 达成后 |
| Env Recipe `outcome` 非空（配方→执行→结果三元组完整） | ≥ **20 条** | 同上 |
| 图像回流（`image_consent.captured=true`，带明确 license） | ≥ **50 张** | 同上 |

> 数据飞轮的真正启动点是 G2，不是 G1。**G1 之前的一切产出都是"资产已备、引擎已通、缺油"。**

### G3 · 三级目标（有回流后才谈）

> **在方法深度上形成可对外定价的能力，并验证付费意愿。**

- 累计外部调用 ≥ 10 万次、日调用 ≥ 500 次连续 14 天
- ≥ 5 个独立来源主动询问价格 / 许可 / SLA
- 方法深度护城河：**双源校准 + 偏差校正 + 数据血缘 + 配方安全门禁**（这是 FieldMCP 等数量型竞品做不到的）

## 三、边界（明确不做清单，附重新打开条件）

> 规则沿用 `north_star_and_phase_gates.md §5.1` 的体例：每条写明**判定依据**与**重新打开条件**，目的是避免重复争论。

|---|---|---|---|
| N1 | **原生 C 端 App（iOS/Android）** | 需企业主体 + 软著 + ICP 备案；市场已被花伴侣 / 百度农小蜜 / 小红书 / 微信识花占满且全免费；Env Recipe 对 C 端用户价值为零（用户要"拍照识病"，不要参数集） | 出现明确付费需求信号（≥5 个独立来源问价） |

| N6 | **链路数据中台（L4）** | 当前只有 1 个 JSON Schema、0 行实现；其变现路径（帮生鲜企业降损分成）属已判不做的 B 端 SaaS | G3 达成且确有生鲜企业对接机会 |
| N7 | **社区 / 城市合伙人 / 数据市场（L5/L6）** | 属运营生态，无用户基数时是空转 | G2 + G3 双达标 |

## 四、技术边界（零依赖约束的正式细化）

> 原约束"纯 Python 标准库、零第三方依赖"既是**护城河**（可复现、可离线、可审计、可私有化部署），也是**天花板**（否掉了视觉诊断精度、栅格数据处理）。正式细化为：

**核心规则**

1. **核心计算与数据路径必须零第三方依赖**（`agent/` `core/` `engine/` `mcp/` 的 import 只允许标准库）——这条不可让步。
2. **增强能力允许依赖，但必须满足三个条件**：
   - 通过 `AGRI_*` 环境变量插拔；
   - 未配置时**降级且不中断主流程**（现有 `agent/vision.py` 即此模式）；
   - 降级状态必须在输出中**显式标注**（如 `confidence=low` / `model=rule_based`），不得静默伪装。
3. **数据获取遵循"本地优先"**：外部数据一律落到 `data/` 本地缓存，运行时优先读缓存；离线可用为默认状态。
4. **绝不引入**：需要 GPU、需要账号体系、需要链上签名的运行时依赖。

## 五、法务红线（优先级高于任何商业设计）

> **在拍板任何定价之前必须先解决本条。**

| 事实 | 证据 |
|---|---|
| 116 份配方 `sources[]` 含 FAO 来源，许可为 `CC BY-NC-SA 3.0 IGO`（**NC = 非商用**） | `data/env_recipes/*.json` 实测 |
| 配方自身 `license_scope` 字段明文："**含 FAO/FAOSTAT（CC BY-NC-SA，非商用）来源时，整包不得作为付费资产转售**" | 同上 |
| `docs/pricing_strategy_2026-09-30.md` 的 Pro($49) / Enterprise 档卖的是"数据访问 + 可商用 + 白标授权" | 该文档 §3 |

**定案（二选一，本文判定采用方案 A）**：

- **方案 A（采纳）**：付费标的**不是数据本身**，而是**服务能力**——接入配额、优先响应、定制分区建模、企业部署支持。数据始终免费开源（与 `commercialization_assessment` 的"N4 边界"一致）。**改动最小，且强化既有边界。**
- 方案 B（备选）：为付费档剥离全部 NC 来源，重新生成合规子集。成本中，且会削弱配方完整性。

**配套要求**：`sources[]` 每条必须补齐 `source_license`（逐条许可）+ `data_quality`（`measured`/`interpolated`/`modeled`/`estimated`）+ `trial_location`——混合许可下这是**法务刚需，不是优化项**。
