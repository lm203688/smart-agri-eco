## 2. MCP 分发（唯一主力路径）

### 2.1 为什么是现在（2026-09 的关键窗口）

三个近期事件直接改变 MCP 的分发经济模型：

| 事件 | 日期 | 对本项目的意义 |
|---|---|---|
| MCP 2026-07-28 规格移除 session（SEP-2575/2567/2243/2549/414） | 2026-07 | Env Recipe 天然符合"显式 handle"模式（recipe_id 由模型持有），**不用重构**——但这是**下一个客户端版本前的死线** |
| Agent Plugins 1.0.0（Google 发布，TSC = Amazon+Cursor+MS+OpenAI+Vercel+Google 6 家） | 2026-08-06 | `plugin.json` + `skills/SKILL.md` + `mcp.json` 一个目录跨 5 家客户端通用，**加一层目录约定**就能同时进 5 家市场 |
| X 托管 MCP server（$0.01/call） | 2026-06-30 | "MCP 单价化"是 2026 下半年关键商业事件，同类锚点：Bright Data $1.50/1000、Exa $7/1000、Composio $29/200K |

### 2.2 具体动作（按 ROI 排序）

**P0 —— 立即做（1-3 天，零依赖）**

1. **适配 MCP 2026-07-28 无 session 规格**
   - 检查 `mcp/server.py` 是否依赖 session 状态；若依赖需改为显式 handle（`recipe_id` / `basket_id`）
   - 本项目 10 个工具当前已符合无状态设计（每次调用传参 → 返回 JSON），**大概率无需大改**——但**必须验证**
   - 工作量：小；风险：客户端新版上线即失效

2. **加 Agent Card（A2A v1.0）**
   - 在 `mcp/agent.json` 或 `/.well-known/agent.json` 放一个 JSON：agent 名、能力列表、认证方式、版本
   - A2A v1.0 已进 Linux Foundation AAIF（与 MCP 同一基金会），加这一个文件零成本
   - 工作量：小；参考：aishield 可先做同套模板

3. **打包成 Agent Plugin 目录**
   - 加 `plugin.json` + `skills/` 目录（本项目已有 9 Skill）+ `mcp.json`
   - 目标：一次开发进 Amazon Bedrock / Cursor / Claude / MS Copilot / Vercel / Google 6 家市场
   - 工作量：中（目录约定 + 描述文件）

**P1 —— 一个月内做（1-2 周）**

4. **上架 Glama + Official MCP Registry + Smithery**
   - aishield 已跑通 Glama 流程，抄模板即可
   - Official MCP Registry 上次返 404 需重测
   - 工作量：小

5. **加 CMIP7 数据源（2026-09-01 公开发布底层排放数据）**
   - 7 个情景（H/HL/M/ML/L/L/VL/LN），2100 升温 1.6-3.3°C
   - 让 `agri_season_advisory` 工具支持"未来 30 年播期窗口"——这是**当前没有任何竞品有的功能**
   - 工作量：中（解析 + 加工具）

**P2 —— 有真实用户后做**

6. **考虑 MCP 单价化**
   - 现在实施过重，但架构上要留 `call_id` + `billing_hint` + `预算上限参数`
   - 触发条件：月调用 >10k 时启动

## 3. C 端 App：为什么不做原生

### 3.1 硬约束（不可绕）

- **上架 iOS/Android 需要**：企业开发者账号（$99/年 or ¥688/年）、软著、ICP 备案、实名认证、Apple Developer Program 需要公司主体、Google Play 需要公司主体
- **中国大陆 iOS 上架要求**：App Store 中国区必须企业主体，个人或工作室无法上架
- **软著申请周期**：30-60 个工作日，且要代码审计报告

### 3.2 市场现状（拥挤程度）

C 端家庭园艺/阳台种植 App 市场已经是**红海**：

| 竞品 | 现状 | 威胁 |
|---|---|---|
| 花伴侣（花加/花礼） | 老牌 App，装机量百万级 | 强 |
| 百度农小蜜 | 免费、AI 拍照识病、覆盖 350+ 作物 | **极强**（免费 + 大厂技术） |
| 小红书/抖音阳台种草 | 生态内容免费、社区粘性强 | 极强（免费 + 内容驱动） |
| 微信"AI 识花"（微信内置） | 免费、微信生态内 | 极强（免费 + 分发） |

**本项目能做什么差异化？**
- 有 Env Recipe 可执行配置（温湿/光谱/PPFD/CO₂/EC/pH 全套）
- 有 110 份配方
- 有 Agent-native 可机读

**但这个差异化对 C 端用户无意义**——C 端用户想要"拍照识病"（已有一堆免费版），不要"可执行参数集"。Env Recipe 的价值对 C 端用户是零。

### 3.3 结论

**❌ 不做原生 App**。

若必须做用户触点，走 **微信小程序**：
- 无需企业主体即可申请（个人主体）
- 无需上架审核（微信侧审核宽松）
- 免费拍照识病 → 引导到 Env Recipe 内容订阅
- 目的是**为 MCP 分发导流**，不是独立产品

工作量：中（3-4 周），前提：用户本人有小程序主体（个人微信 + 身份证）。

## 4. B 端 SaaS / API 订阅：为什么不做

### 4.1 销售模式不匹配

B 端农业 SaaS 需要：
- 行业销售团队（本项目无）
- 售后工程师（本项目无）
- 客户案例（本项目 0 真实用户）
- 合规资质（数据安全评估、隐私政策、SLA 承诺）

**本项目 477 项单测、110 配方、47K 实体是**给 agent 用的结构化数据**，不是给农业企业用的生产系统**。要转 B 端产品化，需要**重新做**（不是叠功能），工作量是"新做一个产品"，不是"完善当前项目"。

### 4.2 潜在 B 端画像与判断

| B 端画像 | 是否可能 | 理由 |
|---|---|---|
| 垂直农业厂 | 极低 | 已有供应商绑定（Priva/HortAitech/Premier），不愿换 |
| 城市农场/合作社 | 中 | 但预算 ¥5-20K/年，销售成本 > 收入 |
| 高校/科研院所 | 高 | 但付费意愿低（用开源免费） |
| 农业科技创业公司 | 高 | 但都是同行，会自己搞 |

**判断**：**唯一可推的是科研院所**（科研场景付费能力弱但接受度高），走「数据引用 + 引用致谢」路线而非 SaaS 订阅。

### 4.3 结论

**❌ 不做 B 端 SaaS**。走**科研引用**路线（免费、开源、要求引用），换学术影响力。

## 5. Env Recipe 数据授权：为什么暂缓

### 5.1 数据本身不稀缺

竞品对照（见 `docs/competitive_scan_2026-09-17.md`）：
- FAO GAEZ v4：CC BY 4.0，全球作物适配性
- WorldClim：CC BY 4.0，气候数据
- ISRIC SoilGrids：CC BY 4.0，土壤数据
- USDA Plant Guides：公有领域

**本项目 Env Recipe 的价值**不在数据本身（都是这些开放源），在**组织方式 + 可执行配置 + Agent-native**。这三个价值**在开源分发模式下反而更强**（数据越流通越有价值），一旦变成付费授权就自我削弱。

### 5.2 结论

**❌ 暂缓数据授权**。等 MCP 分发做出真实调用量（月 10k+），再考虑分层：
- 免费层：基础 110 配方 + 公开数据源
- 付费层：定制配方 + 校准结果回流 + 优先 API 配额

现在做等于给没有用户的产品定价。

## 6. 免费换数据模式：为什么停止投入

### 6.1 事实

- `data/feedback_log.json` 长期 **0 条**
- 通路健康（13/13 检查通过）
- 意味着：**通路能转，但没人用**

### 6.2 判断

这不是技术故障，是**产品-市场不匹配**：
- 免费入口存在（`app/index.html` 前端 + MCP 工具 + Glama 市场）
- 但没有产生回流数据

**结论：不再投入"免费换数据"这个模型**。当前项目的核心资产（110 配方 + 47K 实体 + 358 单测）应作为**开源分发基础**去换生态位，而不是等待自然用户。

**替代模型**：**生态换分发**——把 MCP server + Agent Card + Agent Plugin 铺到能触达的每一个 agent 客户端市场，靠"被调用次数"而不是"用户回流"衡量价值。
