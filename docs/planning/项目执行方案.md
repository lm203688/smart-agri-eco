> 本文件把方案落成**开发任务 + 运营任务**，供各阶段团队直接领取。

## 一、总体执行逻辑（商业项目思路）

商业项目的主线永远是：**选点 → 验证 → 复制 → 变现 → 生态 → 中轴**。每一个阶段都必须构成一个「**最小可闭环的生意**」——即：有用户用、有数据回、有收入/分成的雏形，然后才谈下一阶段。

- 开发轨与运营轨**双轨并行**：开发负责「系统能自动转起来」，运营负责「有人用、有数据回、有钱进」。
- 每阶段一个**北极星指标**，一个**决策门**：指标不达标，不进入下一阶段。
- 一切任务都要回答两个问题：①它是否服务于「自动化」？（能不能少用人）②它是否为数据飞轮输入？（能不能让模型更准）

### 执行主线与切口的关系

```
切口1 生长监控与管理  → P0 入口（粘性 + 数据入口）
切口2 选址与规划引擎  → P1 加深（决策入口 + 标准化）
切口3 链路与鲜度中枢  → P2 变现（B端利润引擎）
切口4 数据与模型服务  → P3 收口（中轴出口）
```

先聚量，再加深，再变现，最后收口——顺序不能乱。

## 二、主要切入点（按推进顺序）

| 优先级 | 切口 | 一句话 | 满足的切口准则 | 目的 |
|---|---|---|---|---|
| P0 入口 | **切口1 生长监控与管理** | 监控→分析→决策→执行→通知的 AI 闭环 | 粘性★ 标准化★ 数据入口★ 数据对接★ | 聚用户、转飞轮、验同构 |
| P1 加深 | **切口2 选址与规划引擎** | 回答「这块地能不能种、种什么、怎么规划」 | 标准化★ 数据入口★ | 决策入口、环境数据体系 |
| P2 变现 | **切口3 链路与鲜度中枢** | 把「事后溯源」变「事前预测+事中拦截+AI提效」 | 标准化★ 粘性★ 数据入口★ | B端利润、链路数据体系 |
| P3 收口 | **切口4 数据与模型服务** | 世界模型与脱敏数据的对外输出 | 标准化★ 数据对接★ | 中轴出口、项目收口 |

> 四个切口全部通过「粘性 × 标准化 × 数据入口 × 数据对接」四准则筛选；其余方向一律不做。

## 三、七层布局总表（谁在哪一层卡什么位）

| 层 | 关键卡位 | 落地模块 | 驱动切口 | 启动阶段 |
|---|---|---|---|---|
| L0 数据底座 | 微气候选址 · 地块环境库 · 农业知识图谱 | 地理数据服务、微气候模型、地块库 | 切口2 | P1 |
| L1 感知 | **传感接入协议**（农业版 HomeKit） | 接入网关、协议 v1、设备 SDK | 切口1 | P0 |
| L2 模型 AI | 世界模型微调 · 决策引擎 · 预测系统 | 视觉模型、诊断/决策引擎、产量/鲜度预测 | 切口1/2/3 | P0 持续 |
| L3 执行控制 | 控制策略层（告诉设备该干什么） | 指令下发、设备适配层、执行补偿 | 切口1 | P0-P1 |
| L4 业务支撑 | **链路数据中枢 · 鲜度模型** | 链路中台、损耗核算、动态调度 | 切口3 | P2 |
| L5 消费服务 | 信任认证 · 即食出口 | 认证体系、社区交易、采摘即食匹配 | 切口1/3 | P1-P2 |
| L6 运营生态 | 社区 · 城市合伙人 · 数据市场 | 社区产品、合伙人网络、数据市场 | 收口 | P1-P3 |

**要点**：七层不必一次全建。L1/L2/L3 随切口1 在 P0 先动；L0 随切口2 在 P1；L4 随切口3 在 P2；L5/L6 贯穿其后。层是「横切面」，切口是「业务切入点」，每个切口把相关层串成一个闭环产品。

## 四、分阶段开发任务与运营任务

### Phase 0｜种子验证（0-6 个月）

**阶段生意闭环**：30 个个人 + 3 个小型农场，用同一套「种植单元」系统完成「建档→监控→建议→成长报告」，验证粘性与飞轮。

**北极星指标**：监控周活跃率 ≥3 次/周；数据回流质量合格率 ≥80%。
**决策门**：飞轮不转（活跃/数据不合格）→ 不进入 Phase 1。

#### 开发任务
| # | 任务 | 交付物 | 归属层 |
|---|---|---|---|
| D0.1 | 定义「种植单元」数据协议 v1（环境×生长×操作×结果，含字段、单位、质量规则） | 协议文档 + Schema | L1 |
| D0.2 | 传感接入网关 v0.1（手机传感器 + 1-2 款蓝牙设备接入） | 网关服务 + 设备适配 | L1 |
| D0.3 | 视觉识别 v0.1（生长阶段、病虫害、缺素、成熟度；起步覆盖番茄/生菜/香草） | 视觉模型 + 推理服务 | L2 |
| D0.4 | 诊断与决策引擎 v0.1（农艺规则库 + 简单模型 → 农事建议） | 决策服务 | L2 |
| D0.5 | 自动化执行 v0.1（对接 1-2 款水肥设备，指令下发） | 控制指令模块 | L3 |
| D0.6 | 用户端 MVP（建档 → 拍照监控 → 建议 → 成长报告 → 通知） | App/小程序 | L2/L3 |
| D0.7 | 数据回流管线（采集→清洗→半自动标注→入池） | 数据管线 | L1 |
| D0.8 | 后台（数据看板 + 数据质量监控 + 简单 AB 能力） | 管理后台 | — |

#### 运营任务
| # | 任务 | 关键动作 | 目的 |
|---|---|---|---|
| O0.1 | 种子用户招募 | 阳台种菜社群/小红书/农场主圈，招募 30 人 + 3 个小型农场 | 聚第一批单元 |
| O0.2 | 成功率基线采集 | 记录每单元「建档→采收」全过程，建立成功率基线 | 飞轮起点 |
| O0.3 | 轻标注协作 | 引导用户对「是否病虫害/长势评级」做轻量确认 | 数据标注降本 |
| O0.4 | 成长日记内容 | 每日精选监控案例、成长日记模板、采收菜谱 | 粘性 + 传播 |
| O0.5 | 晒成果激励 | 里程碑庆祝、首个采收成就体系 | 留存 |
| O0.6 | 双端同构验证 | 对照记录：同一系统服务个人与农场，差异点清单 | 验证单元化抽象 |

### Phase 1｜网络化（6-18 个月）

**阶段生意闭环**：协议开放 + 设备商接入 + 社区上线 → 免费工具聚量 → 订阅转化；选址引擎让「先规划再种」；首个付费农场客户出现。

**北极星指标**：活跃种植单元数 → 10 万。
**决策门**：网络不活（单元数/设备接入/社区不达标）→ 不进入 Phase 2。

#### 开发任务
| # | 任务 | 交付物 | 归属层 |
|---|---|---|---|
| D1.1 | 传感接入协议 v1 公开发布（文档 + SDK + 认证流程） | 开放协议 | L1 |
| D1.2 | 设备商接入体系（认证、联调、分成结算） | 接入平台 + 50+ 设备适配 | L1 |
| D1.3 | 选址与规划引擎（宏观气候/土壤/水文 API 接入 + 微气候模型 + 农事日历生成） | 选址引擎 | L0/L2 |
| D1.4 | 车载种植端 MVP（远程监控 + 颠簸/能源补偿原型） | 车载端 | L1-L3 |
| D1.5 | 社区产品（UGC、排行榜、达人、城市合伙人空间） | 社区 | L6 |
| D1.6 | 农场 B 端版本 v0.1（多单元管理、批量监控、报表） | B端产品 | L2 |
| D1.7 | 数据中台升级（分形态/分地域数据池、数据资产目录） | 数据中台 | L0/L1 |
| D1.8 | 模型迭代管线自动化（自动重训、版本管理、效果回测） | MLOps | L2 |

#### 运营任务
| # | 任务 | 关键动作 | 目的 |
|---|---|---|---|
| O1.1 | 设备商生态 | 招募 50+ 设备商接入，联名与分成签约 | 生态化落地 |
| O1.2 | 城市合伙人 | 首批 5 城线下「植物空间」（社区农场/屋顶/门店） | 线下节点 + 品牌 |
| O1.3 | 内容生态 | 达人孵化、种植课程、短视频矩阵 | 获客 |
| O1.4 | 订阅转化漏斗 | 免费→订阅定价、付费点设计（多单元/深度诊断/选址） | 盈利化起步 |
| O1.5 | 标杆农场 | 每城 1 个社区农场/小型农场作为样板案例 | 说服 B 端 |
| O1.6 | 车载合作试点 | 与 1-2 家车厂/露营/户外品牌做原型合作 | 差异化卡位 |

### Phase 2｜中轴化（18-36 个月）

**阶段生意闭环**：全球数据源接入 + 优化引擎 + 链路鲜度中枢 → B 端分成收入成为主收入；数据与模型服务开售。

**北极星指标**：世界模型预测准确率；B 端分成收入。
**决策门**：模型不优于经验基线、客户不降损 → 不进入 Phase 3。

#### 开发任务

| D2.2 | 全局优化引擎（资源最佳配置求解） | 优化服务 | L2 |
| D2.3 | 链路数据中台（生产→初加工→封装→运输→存储→深加工全链路打通） | 链路中台 | L4 |
| D2.4 | 鲜度模型 + 损耗/需求预测 + 动态库存 | 鲜度/损耗/需求服务 | L4 |
| D2.5 | 分级分拣视觉 + 动态路径调度（联合伙伴） | 提效模块 | L4 |
| D2.6 | 数据与模型服务平台（API / 报告 / 模型授权） | 服务平台 | L2 收口 |

**北极星指标**：生态 GMV / 数据市场交易额 / 标准采用数。

## 五、双轨协同机制（开发 × 运营）

每个阶段，开发与运营在以下**联动点**对齐，避免两轨脱节：

| 联动点 | 开发提供 | 运营反哺 |
|---|---|---|
| 数据协议 | Schema 与文档 | 真实字段使用反馈 → 协议迭代 |
| 模型效果 | 识别/决策准确率 | 用户真实结果标注 → 训练样本 |
| 转化漏斗 | 订阅/分成结算能力 | 定价与流失数据 → 产品取舍 |
| 生态接入 | 设备/数据源接入工具 | 伙伴招募与 SLA 反馈 → 协议改进 |
| 阶段决策门 | 北极星指标数据看板 | 运营归因报告 → 是否过关 |

**例会节奏**：每周一次「数据会」（看北极星与飞轮转速）；每月一次「决策门预审」；每季度更新三份母文件。

## 六、任务优先级速查（按阶段）

| 阶段 | 优先做 | 坚决不做 | 北极星 |
|---|---|---|---|
| P0 | 种植单元协议、监控闭环 MVP、数据回流管线、种子用户 | 不做硬件/不做重运营/不做多形态并行 | 监控周活跃率 |
| P1 | 开放协议、设备生态、社区、订阅转化、选址引擎 | 不扩形态、不做链路（太早）、不烧投放 | 活跃种植单元数 |
| P2 | 全球数据源、优化引擎、链路鲜度、B端分成 | 不脱离数据飞轮做功能、不重资产 | 模型精度 + B端分成 |
| P3 | 数据市场、标准主导、全球化、地外预研 | 不做与中轴无关的多元化 | 生态 GMV/标准采用 |

---

## 总结

> 切入点就四个，顺序固定：**监控（入口）→ 选址（加深）→ 链路（变现）→ 数据服务（收口）**。七层横切面跟着切口走，不提前建层。每阶段一个北极星、一个决策门、一组开发任务 + 一组运营任务，双轨在数据协议、模型效果、转化漏斗、生态接入四个联动点对齐。全局准则不变：自动化、生态化、盈利化。
