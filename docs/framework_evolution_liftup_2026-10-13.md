### 4.2 壁垒分级与建造顺序（本报告核心框架）

```
S 级（不可替代性最高，均需时间，无法速成）
  ├─ S1 实测校准数据集        ← G2 后启动（外回路，依赖用户）
  ├─ S2 机制作物模型方法论文   ← 从 PCSE/WOFOST 论文重实现，可署名引用
  └─ S3 专家盲评配方库         ← 3-5 位农艺专家，闭合 eval_recipe_expert_adoption

A 级（现在就能建，不依赖外部调用）
  ├─ A1 Köppen-Geiger 气候分类引擎（第一环，全链正确性地基）      ← 最高 ROI
  ├─ A2 AgriRecipeBench 扩展（补 SNWM 第三/四轴：反事实 + 跨情境泛化）
  ├─ A3 可信标记产品化（"经 AgriTrust 背书"成为可引用的质量标签）
  └─ A4 Env Recipe 协议对外发布（AgStack 提交 = 标准话语权）

B 级（工程差异化，维持但不加重）
  └─ B1 零依赖 / 数据卫生 / 棘轮门禁（已有，转为"对外可展示的工程能力"）
```

**深挖结论（对上版"技术壁垒 3.0/10"的修正判定：4.0/10）**：
壁垒从 3.0 升到 4.0，**全部增量来自 A2（AgriRecipeBench）与可信三件套**——即"**可验证性**"这个方向。这验证了一个判断：**本项目唯一能建的壁垒不是"数据更多"或"工具更多"，而是"证明更强"**——因为竞品可以复刻数据，但复刻不了"每条输出都带可独立复算的证明 + 有公开评测协议约束自己"的纪律。**下一步把 A1（气候引擎）做实，壁垒即可到 5.0；S1/S3 随 G2/G3 自然启动。**

### 6.4 自进化（Self-Evolution）——本报告最深挖的维度

#### 现状：一个被低估的事实——**自进化骨架已成型，且是前沿对齐的**

逐行实读 `engine/`（4,969 行）后确认：本项目已建成一套**结构完整的自进化骨架**，五大件齐全：

```
┌────────────────────────────────────────────────────────────┐
│  度量层  engine/rsi.py    RSI L1-L5 五级自主权 + HCI        │
│          （每级必须有真实产物证据，防"规划里写了"计达成）      │
├────────────────────────────────────────────────────────────┤
│  内回路  engine/evolution.py  benchmark→评估→编辑→棘轮接受     │
│          （仅严格提升才保留 + 快照回滚 + 隔离副本）             │
├────────────────────────────────────────────────────────────┤
│  外回路  engine/flywheel.py   用户回流→adapt_score 校准        │
│          （真实写盘 + 数据卫生门禁）                            │
├────────────────────────────────────────────────────────────┤
│  经验层  skill_factory / long_term_memory / org_memory /     │
│          context_compact（经验→技能→记忆→上下文压缩全链）       │
├────────────────────────────────────────────────────────────┤
│  度量子层 harness_tree（六层组件）+ manifest（机读基线）        │
└────────────────────────────────────────────────────────────┘
当前状态（本次实跑 engine.rsi）：L1 未闭合（execution_log/feedback 0）；
calibration 0 作物；skill_generation 1 个但 0 引用；HCI 低位。
```

**这是同类开源农业项目里几乎独一无二的资产**——但它现在只是"内部质检工具"，不是"系统能力"。且存在一个结构性问题：**两条回路里，外回路（依赖用户）0 数据，内回路（离线棘轮）有能力但只覆盖 calibrate 权重一个场景**。

#### 提升方案（S1-S6）：构建"受控自进化系统（Bounded Self-Evolution）"

核心设计原则：**自进化必须先有"不可进化区"（immutable core），再有"可进化区"（evolvable shell）**——否则"自我改进"会侵蚀项目唯一真实的资产（诚实性与可复现性）。

| # | 提升 | 方案 | 判定标准 |
|---|---|---|---|
| **S1** | **声明不可进化区** | 明文定义：可信层/数据卫生门禁/协议契约/schema 兼容性 = **不可进化**（防自改进侵蚀可验证性）；科学参数/技能库/编排策略 = **可进化**（棘轮约束下） | 写入 CORE_OBJECTIVE 附录，机读化 |
| **S2** | **内回路扩展为全科学模块的 CI**（**不依赖外部调用，现在就能转**） | evolution benchmark 从"仅校准权重"扩展到：气候引擎、物候、预测、配方生成——每个模块一组不变式用例（如"积温单调性""产量区间包含关系""配方安全门禁"），棘轮裁决 | CI 绿 + 棘轮拒绝过一次退步用例 |
| **S3** | **内回路喂给 AgriRecipeBench** | 内回路 benchmark 与 AgriRecipeBench 归一：同一批用例既服务"改进裁决"又服务"对外测评"——一套数据两个用途 | 用例库共用，bench 5/5 记录在 CI |
