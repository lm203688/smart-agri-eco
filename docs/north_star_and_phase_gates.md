## 3. 推进规则

1. **阶段不可跳**：G0→G1 的所有门槛必须全绿才能进入 G1→G2 的动作。
2. **阻塞项优先**：门槛 1（PAT + 推送）阻塞 G0→G1 的所有后续动作——推送不通，Glama/npm 上架无从谈起。
3. **回流优先于规模**：门槛 7（500 次调用）与门槛 9（30 条回流）不要求同步达标，但 G2→G3 必须两条都过。
4. **指标不可编造**：所有「当前值」只能来自实跑输出或一手探测，禁止填入估算值。本文件的 ⚠️ 标记表示「当前不可测」，不可用 0 充数——不可测就是不可测。
5. **每次推进都要留痕**：达到门槛时在 `.workbuddy/memory/` 当日日志记录「门槛 N 达成 + 证据来源」。

### 5.1 农业项目投资评估板块 —— 结论：**现在不做**（2026-09-20 评估）

**用户提问**：把「农业项目投资评估」板块放进项目，是否合适？

**判定：现阶段不合适，四个理由，每条都有实证。**

| # | 理由 | 实证依据 |
|---|---|---|
| 1 | **前置数据不存在，硬做只能编造** | 实扫 110 份配方：`outcome` 非空 **0 条**、含 yield 字段 **0 条**；全库递归扫描 price/cost/cny/usd/yield/roi/revenue 字段名 **0 命中**。投资评估的核心输入（成本、产量、价格）在项目里一个都没有。填假设值就等于编造数字，与本项目「不编造」原则直接冲突 |
| 2 | **本质是 B 端需求，撞已判「不做」的路径** | 需要投资评估的人是投资者/金融机构/政府项目评审/农场经营者——这是机构端。而 `commercialization_assessment_2026-09-19.md` 已判 B 端 SaaS 不做（无行业销售、无客户案例、需重新产品化）。加投资评估板块等于把已判不做的路径从后门放回来 |
| 3 | **数据无壁垒，与护城河论证相悖** | 项目判断「数据库本身不是壁垒」。投资评估的数据（电价、种苗价、设备价、行情）**比农业数据更没有壁垒**——任何人都能查。放进来越多，项目越像"农业杂烩"而非"环境配置引擎" |
| 4 | **与主线正交，不产生 Env Recipe** | 主线是"让 agent 拿到可执行种植配置"。投资评估消费配置，但不产生配置——它是下游决策层，与 110 份配方 + 10 MCP 工具的主产物没有生产关系 |

**唯一可能成立的形态**（不作为板块，作为单个 MCP tool）：

`agri_project_roi`——输入一个部署方案（设备清单 + 面积 + 周期），输出回收期/盈亏平衡的**区间估算**，**明确标注所有成本参数为外部假设、由调用方覆盖**。这个形态成立的前提是：

- 成本参数**由调用方传入或查公开源**，本项目绝不内置硬编码价格（否则就是编造）；
- 输出标注"基于假设参数，非预测"，不做点估计；
- 只有当门槛 9（`feedback_log` ≥ 30 条真实回流）达成后，才能用真实 outcome 把假设参数替换成项目自有校准值——**那才是投资评估从"计算器"升级为"有数据支撑的评估"的分界线**。

**重新打开的条件**（满足任一即可重新评估，不必等全部）：

1. 门槛 9 达成（真实回流 ≥ 30 条）→ 有了真实产量，才有真实 ROI 可言；
2. 门槛 14 达成（≥ 5 个独立来源主动问价格/成本）→ 有真实需求信号；
3. G2 达成后有调用方明确要求「给 agent 用的 ROI tool」→ 作为 10 MCP 工具的第 11 个工具，成本极低。

**2026-09-20 实际发生（记录判定被部分推翻的方式）**：第 10 个工具位被 `agri_bp_screen` 占用——**但不是 ROI 计算器**。用户交出的 AgriScreen 输入是 BP/审计/流水**文本**（不依赖本项目种植数据），输出是完备性+风险初筛三档（不产出 ROI 数字），且自带三重防编造（无来源不计分 / 缺失区间化 / 合理性校验 L2.5）。它绕开了上表第 1 条的硬阻塞（前置数据不存在），因为它的输入是外部文本而不是本项目 recipe。判定「投资评估板块不做」仍然成立；被推翻的只是「唯一可能形态是 ROI 计算器」这个具体猜测——**真正的成立形态是「不需要种植数据的决策辅助层」**，而 `agri_project_roi` 仍维持「不做」。

**在条件未达成前的正确动作**：不做。任何"先用假设数据搭个框架"的做法都会污染项目的可信度资产，而可信度是本项目唯一实际拥有的东西。
